# Code review — 2026-09-30 (v1.22.0 → v1.23.0)

Whole-codebase review with a focus on Quests. Three passes (quests; engine /
data / notifications; UI / app shell), every finding re-verified against the
code before acting. Everything under **Fixed** ships in v1.23.0; the rest is
recorded here with a recommendation.

## Fixed in v1.23.0

### Quests
- **A step walked twice was already "done".** Progress and answers were keyed
  by step id, so a quest that loops back (a question answering "again") found
  its tasks pre-ticked on the second visit, judged late completions against the
  first visit, double-counted the step in the completion, and never ended.
  Progress is now keyed by **position in the path** (`<index>/<task id>`,
  `decisions[index]`); existing runs are migrated on load (`plans.js
  migrate`). A repeated step is fresh each time and pays in full.
- **Quest sheet crashed** after an answer already chosen was removed from the
  question in a run edit (`dec.options[i].label` on `undefined`). Guarded;
  shows "End of the quest" for a vanished answer.
- **Hostile share code threw** instead of being refused (a `null` step in the
  JSON): the boot code and the import preview both crashed. `importCode` now
  returns `null` for anything malformed.
- **Shared link lost for a first-time user**: the hash was cleared before
  onboarding and never came back. It is kept and offered once the setup ends.
- **Editing a running quest could revert its progress**: the whole clone was
  assigned back (`status`, `path`, `finished` included), so a quest finished by
  the ticker while the editor was open got paid twice on save. Only `name`,
  `emoji`, `blocks`, `root` come back now.
- **Start in the past** was possible via the date field (whole quest walked
  instantly, 0 %). Refused in `start()` and in the sheet.
- **Rest steps paid**: a taskless step counted as 100 %, so a 30-day quest
  with no task was worth 3 000 pts. Rest steps now weigh nothing in the
  completion (they still count in the planned length); an all-rest quest pays 0.
- **Infinite quests**: the editor now refuses to save a quest with no way to
  the end (`hasExit`), and flags steps unreachable from the first one (⚠️).
- `fmtDate` was used in `app.js` without being imported → starting a quest
  for tomorrow or a picked date threw after starting (no toast, console error).
- "Day 0 of N" for a quest starting tomorrow → "Starts &lt;date&gt;"; the first
  step of such a quest now appears in "Coming up". Finished list no longer
  capped at 12. Projection capped at 8 steps (loops showed 30). Import preview
  lists tasks and questions, not just counts. Share button on drafts labelled.
- Undo message no longer claims "5 minutes" when the quest is simply over.

### Engine / data
- **Undo minted pause progress**: undoing a completion left the `pauseXp` it
  had filled; undoing a skip fed the refund to `earnPause` as a gain. 8 cycles
  = one free pause token. Undo now uses the plain XP path, takes the pause
  progress back, and refunds only the XP that was really applied (a penalty
  clamped at 0 no longer comes back as +10).
- **Undo of a late completion** re-opened a dead window: the miss was wiped,
  `recovered` stayed, and the next tick re-marked the miss (farming the 🩹
  badge). Late completions are no longer undoable (engine + both UIs).
- **Pause log pruned after 2 days** while statistics read 30 days back: a
  paused day resurfaced as misses in the history chart / comeback badge.
  Kept for 32 days.
- **Clock going backwards** left `lastEvaluated` in the future and froze the
  streak for good. Clamped to yesterday.
- `tick()` crashed when called without hooks (tests / future callers). Guarded.
- **Corrupt save blob** was silently overwritten by the next save; it is now
  kept under `momen2m.v1.corrupt` before defaults are loaded.

### UI / app shell
- **Premade "✕" delete button did nothing**: it carried `data-stop` and
  `data-action` at once, and the stopper won. The handler now lets a stopper
  that is itself the tapped button through.
- **Sheet dismissal contract**: tapping outside or pressing Escape on a step
  sheet dropped the whole quest editor; Escape on the update note ignored
  "don't show again". `openSheet(html, onDismiss)` + `dismissSheet()` make
  both paths equivalent. The boost popup no longer replaces an editor the user
  is typing in (a toast instead when a sheet is open). A shared-quest boot no
  longer swallows the update note (it waits for the next boot).
- `t()` used `String.replace` with a string: `$&`, `$'`, `$1` in a quest or
  moment name mangled toasts. Split/join now.
- Local XSS hardening: slot times in `value=` attributes and list text, and a
  backup file name in the auto-import confirmation, are escaped (only
  reachable through a hand-edited backup or folder — low severity, closed).
- Light theme: `--ok / --warn / --danger` were the dark-theme values (≈ 1.6:1
  on white); darker light-mode values added. `theme-color` follows the colour
  scheme. `#app` no longer an `aria-live` region (it re-announced every
  render); toasts are `polite`. Sheets carry `role="dialog" aria-modal`.

## Known risks, not changed (decisions to make)

- **Late answers backdate the next step** (by design: a step starts the day
  after the previous one ends, whatever day the question was answered). Answer
  two days late and a 1-day step is already over — every task late, no bonus.
  Options: date the next step from the answer day, or ask "start today /
  backdate?" when answering late. Recommended: start from the answer day.
- **Pause hides a moment whose window merely overlaps** the pause: pausing at
  19:30 removes a 08:00–20:00 moment, and pausing at 10:29 dodges a 10:30
  miss. Alternative: only exclude moments that *start* inside the pause, or
  whose remaining window is covered. Whole-day pause leaves the streak
  untouched (`dayComplete` → null), which is consistent but asymmetric with the
  "perfect day" toast.
- **Double alerts with the relay on**: the relay fires `start`/`missed` on time;
  opening the app within 15 min re-fires the in-app notification with the same
  tag. Check `swReg.getNotifications({tag})` in the hooks, or skip in-app
  notifications while push is enabled and freshly synced.
- **Run edits can raise the completion**: removing undone tasks from the
  current step before it ends makes it 100 % (self-cheat only). Freezing the
  task list of a step once it has started would close it.
- `pruneDays` is count-based (45 keys): a burst of future day keys (clock
  jump) would evict real history first. Prune by age.
- `flush()` swallows `QuotaExceededError`: the app keeps running with nothing
  persisting and no signal. Surface a toast once.
- Backup import (`importJSON`) validates only `habits` being an array; a
  hand-edited file with `pauseLog: {}` would crash `.find`. Per-field
  normalisation in `mergeWithDefaults` would harden it.
- `frame()` rebuilds occurrences ~8× a second (tick, rough-patch check, render);
  negligible at 15 moments, but building today/yesterday once per tick and
  passing them down is a small, safe change.

## Suggestions — Quests first

1. **Reminders**: quests have no push. One daily relay item at a chosen hour
   ("2 quest tasks today · a question waits") plus a dot on the tab badge would
   close the biggest gap with moments.
2. **Late answers** → start the next step from the answer day (see above).
3. **Editor**: reorder steps (numbering follows array order, so "→ 3" can come
   before step 2); duplicate a step; a live line "≈ N days · up to X pts if
   flawless"; show the dated preview of steps for a chosen start day.
4. **Scoring**: freeze a step's task list once started; show the expected
   payout in the quest sheet; count lifetime quest points in Progress.
5. **History**: delete / archive finished quests in bulk; per-quest stats
   (times run, best completion) on the template card.
6. **Sharing**: a QR code of the link (canvas, no dependency) for
   phone-to-phone; import from the clipboard in one tap.
7. **Templates**: ship 3–4 example quests (moving flat, exam week, race
   prep) as premade quests, hidden until the tab is opened the first time.

## Suggestions — rest of the app

- Split `ui.js` (1 200 lines: renderers, 14 sheets, toasts, sparkles, diff)
  into `sheets.js` / `toast.js`; the `app.js` click switch (~60 cases) into
  per-area handlers. Dedupe `shake` (×5), `pctText` (×2), `fmtDate(new
  Date(day + 'T12:00'))` (×4 → `fmtDay(key)` in `time.js`).
- `fmtClock(ts, lang)` ignores `lang`; `update.js announce(worker)` ignores its
  argument; ~20 dead i18n keys (`appName, tagline, obPickTitle, …`); `now`
  key duplicated.
- Native `confirm()` in four places while reset/import use the styled
  `openConfirmSheet` — pick one (the sheet).
- Accessibility: switches and selects have no accessible name; clickable
  `div`s (`.occ`, `.item`, `.greet`, `.ag-goal`…) are not focusable; tab bar
  lacks `aria-current`; importance is colour-only.
- Layout: the 5-tab bar has no `min-width:0`/overflow guard for large font
  scales; the top bar wraps to two rows in French at 375 px with four pills.
- Day rollover only re-renders Live and Quests; Progress/Moments/Setup stay
  stale after midnight until a tap.
- Tests to add next: DST day (slot at 02:30), `settlePastDays` with a 46-day
  gap, `mergeWithDefaults` on an old save, the rough-patch detection (move it
  from `app.js` into a testable module), relay double-fire once addressed.
